Retrieval for your AI app shouldn't need a vector database, a server, or a GPU. **RAGite 1.0** is a starting point for doing it in one file.

RAGite is a loadable SQLite extension that brings retrieval-augmented generation (RAG) into your database. It splits your documents into chunks, computes embeddings on the CPU, and finds the best-matching passages with a hybrid search that combines vector similarity and full-text BM25. Every hit links back to its source document and position.

## What it offers

- **A single file, no server.** Documents, chunks, vectors and the full-text index all live in the same SQLite database.
- **Plain SQL.** You write through the document table, and `INSERT`, `UPDATE`, `DELETE` and `ROLLBACK` keep everything consistent.
- **Runs on a CPU.** A default embedding model (potion-retrieval-32M, 512 dimensions) is built in, and you can bring your own.
- **Any programming language.** If it can load SQLite extensions, it can use RAGite.

## A base for tinkering and prototypes

RAGite isn't meant as a finished, one-size-fits-all solution. The chunker, scoring and other presets are fixed per build, on purpose: if you need different behaviour, fork it and change it. The [tinkering guide](https://github.com/pihme/ragite/blob/main/docs/tinkering.md) shows where those presets live and how to add a document type, write a chunker or change the fusion. That makes it a good base for experiments and prototypes.

## Try it in a minute

Grab `libragite.so` from the [latest release](https://github.com/pihme/ragite/releases/latest) (Linux x86-64), then:

```sql
SELECT load_extension('./libragite');
CREATE VIRTUAL TABLE docs USING ragite;
INSERT INTO docs(text, source, format)
VALUES ('# Installation

Run the installer and restart the application.', 'manual.md', 'text/markdown');
SELECT chunk, source, score FROM docs_chunks
WHERE docs_chunks MATCH 'How do I install it?' LIMIT 5;
```

For a bigger example, have a look at the [demo project page](https://pihme.github.io/ragite-demo/).

## What 1.0 means

The SQL interface is stable now. RAGite follows Semantic Versioning, so breaking changes or anything that needs re-indexing will only come with a new major version. The [roadmap](https://github.com/pihme/ragite/blob/main/ROADMAP.md) shows what 2.0 is going to bring.
